# M3-04 AI 动态追问与面试评估报告

> 下文的 M3-04 原始记录保留当时的事实；关于部分复盘数字、重试次数和模型 Token 限制的旧描述，以末尾“M3-04-Fix 收尾验收”为准。

## 目标与完成范围

在既有 `InterviewService` 状态机上实现服务端追问、练习反馈、完整/部分报告及模型操作的认领、租约、失败和重试。本轮未开发 M3-05 前端、未更改题库耗尽时长模式的规则、未创建学习任务，也未增加大型框架或其他依赖。

正式数据库 `interview_presets`、`interview_question_bank` 均为 0 行，**尚无审核通过的正式题库**。[题库草案](../interview/M3-04-question-draft.md)覆盖 Python 后端与 AI 应用，包含知识点、难度、考查目标和参考要点，明确待审核，不自动入库。本轮模型与 API 测试使用单独创建并删除的隔离数据库，未将测试题写入正式数据库。

## 实现与关键文件

- `backend/app/services/interview_ai.py`：复用 M2 `stream_chat`；对追问、练习反馈、完整和部分报告使用 Pydantic 严格结构校验。提示输入仅包含当前场次已正式提交的有效回答及对应问题；报告每一条必须精确引用一条实际回答 ID，引用集合必须完整且无重复。追问最多两条，写入前重新检查当前问题、状态、深度及总量，不允许模型指定编号或状态。
- 部分复盘结构只允许文字总结和按实际回答 ID 关联的文字项，不含评分字段；输出校验拒绝 Unicode 数字字符、常见中文数值评分和评分词，失败时要求重试。它可能拒绝包含合法技术数字的文字，也不能数学上保证识别所有自然语言隐含评分或虚构断言，须在独立评审中关注。完整报告暂采用 0～100 综合分并校验范围，这是当前实现约定，评分量表与质量仍需产品确认。
- 正式模式进行中拒绝逐题反馈和报告；追问只接受问句并过滤常见评价/答案措辞。自然语言过滤是防护而非语义证明，不能保证识别所有隐晦评价或不准确陈述。M3-03 详情仍不返回评分或参考答案。
- `backend/app/api/v1/interviews.py`：新增模型操作、操作查询和报告读取接口；`backend/app/models/interview.py` 及 `0006_interview_ai.py`：增加操作尝试次数和经校验结果表。测试代码位于 `backend/tests/test_interview_ai.py`、`integration_m304.py`、`integration_m304_real.py`。

## API 契约变化

统一前缀 `/api/v1`；POST 均需 M3-03 的 `Idempotency-Key`。同步请求在完成时返回结果，也可能返回 `running`、`failed` 或 `no_content`；不提供 M3 模型 SSE。

| 接口 | 请求 | 说明 |
| --- | --- | --- |
| `POST /interviews/{id}/ai/followup` | `{ "answer_id": "..." }` | 基于当前主问题范围内的最新有效回答生成一条追问，返回操作 ID、状态和题目 ID/正文 |
| `POST /interviews/{id}/ai/feedback` | `{ "answer_id": "..." }` | 仅练习模式进行中可生成文字反馈 |
| `POST /interviews/{id}/ai/report` | `{ "type": "full"\|"partial" }` | 完成场次申请完整报告；提前终止/中断申请部分文字复盘；无有效回答返回 `no_content` 且不调用模型 |
| `GET /interviews/{id}/ai/operations/{operation_id}` | 无 | 查询 `running`/`complete`/`failed`、尝试次数和允许显示的结果；跨场操作返回 404 |
| `GET /interviews/{id}/ai/report` | 无 | 终态报告返回 `ready` 和结果，尚未生成返回 `not_requested`，无有效回答返回 `no_content`；进行中返回 409 |

同键同内容在运行时返回已有操作、成功后返回同一已保存结果；失败或租约过期后用**原请求及原键**重试会再次调用模型并增加尝试数。相同键用于不同操作/目标返回 409；不同键对已生成结果的同一目标返回 409。模型错误以脱敏信息返回失败状态，不输出上游原文、密钥或模型原始响应。

## 事务、租约和成本

认领操作时锁定面试行、核对状态和资格并提交操作记录；模型 HTTP 请求在事务外执行。租约为 90 秒，运行期间每 15 秒短事务续约；无活动检查识别有效运行租约。完成时在新事务中重新取得面试行锁，校验租约所有者/有效期、场次状态、当前问题与追问数量后原子保存结果。用户终止或时间到期后迟到的追问/反馈不落库。模型错误保留已提交答案，标记 `failed`；进程崩溃后租约过期可查询或用原键重新认领，旧执行者不能覆盖新结果。

外部模型调用无法保证恰好一次：崩溃或失败重试可能重复调用供应商并产生费用，但唯一约束和租约防止重复结果落库。每次输入限制约 24000 字符、每次输出限制 30000 字符；并非精确 token 限额，当前适配器未收集 token 用量，也未设置供应商侧 `max_tokens` 或费用上限。本轮隔离数据库共执行 11 次真实 M3 模型调用（追问、反馈、部分与完整报告的多次验证），另一次 M2 真实模型回归；未获取计费数据，无法计算实际费用。

## 待独立评审与遗留问题

1. 正式题库仍待审核入库；时长模式题库耗尽策略仍待产品决定，本轮未修改。
2. 综合分量表/权重及模型评价质量需产品和领域专家评审；输出语义、间接评分和提示注入不能仅靠 JSON schema 与词语过滤完全保证。部分报告严禁数值评分的语义安全及正式模式无隐晦评价应作为独立评审重点。
3. 模型请求无精确 token/费用限额，需部署方配置服务商额度并评估长会话、重试和并发成本。部分报告禁止数字可能误拒正常技术反馈。
4. 没有用户认证和公网访问隔离；旧规则快照兼容仍需方案。中断时可丢失未完成的模型输出分片，但不会丢弃已提交答案。
5. 没有后台 worker：模型操作由发起请求的进程执行，崩溃后依赖客户端查询并用原键重试。无有效租约的异常残留需客户端触发恢复，不能承诺无人访问时自动处理。

建议对 M3-04 的评分安全、正式模式输出及租约故障边界进行独立技术评审；真实模型结构调用已验证，但不将其等同于评价质量验收。未开始 M3-05。

## M3-04-Fix 收尾验收

### 修改与行为

- `backend/app/services/interview.py`、`interview_ai.py`：用户开始和成功提交答案等活动仍使用原有 `last_activity_at`；模型成功、失败和重试不再刷新它。题数模式保留 30 分钟无活动期限，数据库行锁及数据库时间用于惰性判断；有有效租约的操作可继续运行，默认单次总时长限制 120 秒。首次跨过期限的操作结束后给予一次 60 秒恢复宽限，期间失败和重试不刷新宽限；崩溃租约按租约到期时间计算宽限，而非按下一次查询时间计算。新的有效用户活动可重新开启计时。时长模式仍以绝对截止时间为准。无人访问时状态不会立即自动更新；并发终止或时限到期后迟到结果不会写入。
- `backend/app/models/interview.py`、`backend/alembic/versions/0007_interview_model_grace.py`：`interviews` 增加可空时间列 `model_grace_until`，持久化上述一次性宽限；迁移不修改既有 M1/M2 记录。新迁移接续 `0006_interview_ai`，不改写已执行迁移。
- `backend/app/services/interview_ai.py`：部分复盘保持严格结构校验，禁止数值评分字段，并过滤明确评分、常见等级表达；允许 `Python 3.12`、`HTTP 404`、版本号与耗时等技术数字。词语和正则过滤可能误拒正常内容，也无法识别全部隐含评分、保证模型评价真实或防止所有提示注入，不能作为语义安全证明。
- `backend/app/core/config.py`、`backend/app/llm/client.py`、`compose.yaml`、`.env.example`、`backend/.env.example`：新增 `MODEL_AI_MAX_ATTEMPTS`（默认 3 次，含首次）、`MODEL_AI_MAX_OUTPUT_TOKENS`（默认 1024）和 `MODEL_AI_MAX_DURATION_SECONDS`（默认 120 秒）。相同面试、操作类型和目标的尝试跨幂等键累计；达到上限后返回冲突。操作查询失败结果新增 `retryable` 字段。适配器仅在面试 AI 调用时发送 `max_tokens`，原 M2 调用契约不变；上游不兼容时返回明确错误，不降级为无限输出。原有约 24000 输入字符和 30000 输出字符上限继续作为兜底。
- `backend/tests/test_interview_ai.py`、`test_chat.py`、`integration_m304.py`：补充技术数字与评分对照、活动时间、一次性宽限、崩溃租约、跨键累计重试、超时、Token 参数和上游不兼容测试，以及 PostgreSQL 并发与故障场景。本次未引入 V2.5 之外的新依赖，也未开发 M3-05。

### 遗留限制与建议

输出 Token 上限和重试次数可降低单操作风险，但字符预算、Token 上限均不是精确费用上限；没有采集实际 token 计费数据，仍需在模型服务商配置额度。自然语言评分过滤存在漏判与误判风险；真实模型格式通过不证明评价可信。正式题库、耗尽策略及评分规范仍待产品确认；后台无定时任务，崩溃与无活动恢复依赖请求触发。
