# M3-02 面试数据模型与状态机报告

## 目标与实现范围

实现独立面试数据结构和状态服务，为后续 API 做准备；未实现面试 HTTP API、页面、AI 追问、评分或报告生成，未加入题库演示数据。已确认与推荐规则同步到 `M3-01-design.md`。没有引入 V2.5 之外的新依赖。

`InterviewService` 使用 PostgreSQL 面试行锁，在单个短事务内执行状态检查、幂等检查和写入；不调用模型。支持 `pending → in_progress`，达到时间/题数限制且满足规则门槛后进入 `completed`，以及进行中主动终止 `terminated`、异常中断 `interrupted`。三个终态拒绝新的作答和状态变更；同一幂等请求可读取原结果。重复开始不会重置开始时间，重复结束不会改变终态。

主问题和追问分别编号，最多两层追问且追问不增加主问题数；主问题显式关闭后才处理下一个，题数模式最后一题关闭后才检查完成条件。仅练习允许跳题；跳题不计入有效回答。有效主问题数按不同主问题统计，包括其追问下的有效回答，不会因为多次追问重复计数。有效性的推荐实现为非空文本，与模型评价无关。

`InterviewRules` 集中定义推荐值：2 个不同有效主问题、题数模式至少 3 题、30 分钟无活动、JD 5000 字及非空文本校验。调用方必须显式提供规则；创建时保存数值与校验策略标识，后续配置与快照不一致时拒绝操作，防止静默变更。以上值尚待产品最终确认。无活动检查目前只返回布尔结果，不自动更改状态。

时间限制采用 PostgreSQL `clock_timestamp()`，在锁内检查 `now >= deadline`；达门槛则原子完成，未达门槛时保持 `in_progress` 但拒绝到期后的出题和作答，返回 `expired_insufficient_evidence`。题数达限但不足门槛也保持原状态并返回 `insufficient_evidence`，不允许超额出题；具体如何结束属于未确认规则。检查为请求触发，不会在无人访问时自动执行。用户或后续编排可显式终止/中断。

## 数据库结构

新增七张表，未删除、合并原设计表，均独立于普通聊天：

- `interview_presets`：预设类型、名称、版本、启用及配置；`interview_question_bank`：所属预设、题目、知识点、版本及启用状态，按预设建索引。
- `interviews`：状态、模式、预设及配置快照、JD、限制类型与值、开始/截止/最近活动/结束时间、原因、主问题数、有效主问题数和并发版本；状态建索引。检查约束验证状态、模式、限制、计数及时间字段组合。
- `interview_questions`：场次、主问题编号、父题、追问深度、正文及来源快照、关闭时间；场次索引，场次/题号/深度唯一；复合外键保证父题同场，深度限定 0～2。
- `interview_answers`：场次、题目、回答或跳过、正文、请求标识和提交时间；复合外键保证题目同场，问题唯一、场次/请求标识唯一，检查回答非空和跳题正文为空。
- `interview_reports`：场次、完整/部分类型、独立状态、文字复盘、可空综合分及生成时间；场次索引和类型唯一；数据库禁止部分报告综合分。当前服务仅提供报告占位创建，不接受或生成报告内容、逐题数值或分数，未完成场次不能创建完整报告，无有效回答不能创建部分占位。
- `interview_operations`：场次、操作类型、请求标识、请求体摘要、状态、结果、租约及错误类别；场次/请求标识唯一，重用键且请求不同会拒绝。租约字段为后续工作预留，本轮未实现模型任务调度。

深度递增、父题所属当前主问题、跨表报告状态和正式模式跳题限制由状态服务在场次锁内校验，不能只依赖前端。数据库 CHECK 无法判断自由文字里是否含数字评分；后续报告生成/读取必须采用受约束的文字结构并校验，不能将任意数字评分写入部分报告。

## 代码与服务接口

- `backend/app/models/interview.py`、`backend/alembic/versions/0003_interviews.py`：七张表及约束。
- `backend/app/services/interview.py`：`InterviewRules`、`recommended_rules()` 和 `InterviewService` 的 `create`、`start`、`add_question`、`answer`、`close_main`、`check_expiry`、`check_inactivity`、`end`、`add_report_placeholder`。每次服务方法自行开启并结束事务；调用方应使用空闲 AsyncSession，不能在外部长事务内调用。
- `backend/tests/test_interview.py`、`backend/tests/integration_m302.py`：状态/边界和真实 PostgreSQL 并发测试。后者通过容器内临时代码目录执行，会创建并清理自己的测试场次。

## 遗留问题与 M3-03 依赖

1. 推荐数值与答案有效性策略尚未产品确认；规则快照用策略 ID 防止配置漂移，但调用方需保证同一个策略 ID 始终对应同一实现。未来版本变更应保留旧策略实现。
2. 时间或题数达到限制但证据不足时，场次暂保持 `in_progress`、禁止超额/逾期作答；最终归类、自动终止和无活动超时行为待确认。惰性到期需未来 API 在读取/提交时调用，不是定时任务。
3. 题库尚无经过审核的正式内容；提问题目目前是内部服务输入，未实现 AI 追问或题库 API。题目闭合由后续编排显式调用，必须避免过早关闭当前主问题。
4. 完整/部分报告占位并非生成能力；未完成场次禁止任何数值评分及直接生成学习任务的规则，需在 M3-04 的报告生成和所有 M3-03/后续 API 输出中继续强制。正式模式进行中不得泄露评分评价，也需在 API、SSE 和页面层验收。
5. 数据库表可被绕过服务直接写入，部分跨表约束依赖服务事务；单实例仍无身份认证或公网访问保护。
6. M3-03 开发前应确认不足门槛及超时归类、题库来源、规则取值与策略版本，以及 HTTP 幂等/错误契约；根据产品结论调整状态服务并重新执行 PostgreSQL 并发测试。未开始 M3-03。
