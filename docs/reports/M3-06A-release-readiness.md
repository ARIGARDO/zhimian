### 隔离导入审计发现

1. **已修复：URL 查询参数覆盖连接目标。** `affacb6` 的 `validate_url()` 只看 URL 主机和路径；SQLAlchemy asyncpg 方言可用 `?host=...` 覆盖表面上的 `127.0.0.1`。本轮用方言 `create_connect_args()` 本地验证，未连接远端；现已拒绝全部查询参数和片段，并增加 host、database、fragment 测试。
2. **已修复：测试脚本迁移顺序。** `affacb6` 的集成脚本先验证 URL、执行 Alembic，再检查/建立隔离标记；可能在错误的本机同名前缀数据库执行迁移。现要求事先在隔离实例建立标记，先验证标记再迁移；无标记真实 PostgreSQL 测试已验证拒绝，未进入迁移。
3. **已加固标记查询。** `to_regclass` 检查 `public`，但旧版读取表未指定 schema；现限定 `public.m306b_isolation_guard`，避免 search_path 中的同名对象混淆。
4. **仍有部署边界风险。** 静态标记和数据库名前缀不是身份认证；任何能创建标记的高权限连接都可能伪造隔离标记，本机端口也可能转发到其他实例。工具不检查集群身份，也没有强制独立角色或禁止执行 DDL 的权限。生产环境不得依靠此工具和标记作为安全隔离；应使用独立实例、网络及最小权限凭据，并人工核对集群身份。错误 URL 可能在读取标记前建立连接，不能将这些检查称为网络隔离。
5. 工具必须显式传入 `--database-url`，本体不通过 `get_settings()` 读取 `DATABASE_URL`；集成脚本从 `M306B_TEST_DATABASE_URL` 派生 `DATABASE_URL` 给 Alembic，现先验证目标及标记。命令行 URL 中的凭据可能暴露在进程列表、shell 历史或 CI 日志，应只用临时测试凭据，不把真实密码传在命令行。
6. 清单校验不是内容审查或加密签名，静态 JSON 与摘要只能发现内容变动；模型可能复述内部材料，当前自然语言过滤不保证零泄漏。需要人工及对抗验证。

## 真实模型隔离验收计划——本轮不调用

- **模型版本**：待负责人指定供应商、部署名称及可复现的模型版本/快照；记录适配器、提示词和题库摘要版本。未指定时不执行，也不将“当前默认模型”冒充固定版本。
- **场次**：建议隔离库中 Python 和 AI 方向各 2 场、每场 3 道主问题；将正确完整、部分正确、明显错误、合理替代答案分布于两方向，至少一场包含 1～2 次追问并正常完成。材料均来自已审核测试副本，输入使用合成答案，不包含真实 JD 或凭据。
- **故障与预算**：单独用受控替身验证超预算、超时和接口失败，确认答案保留、结果不伪装完整；它们不计作真实模型效果。真实调用建议每操作沿用输入 24000 字符、输出 1024 Token 和最多 3 次尝试的技术上限，建议整个实验最多 12 次供应商请求（含失败和重试），单次输出不超过 1024 Token、总输出上限 12288 Token，拟定费用上限人民币 5 元；这些上限须先经负责人批准并与供应商实际计费规则核对。输入仍按单次 24000 字符限制，并非输入 Token 上限。实际费用以供应商计量为准，字符上限不能替代费用控制。
- **人工标准**：逐条核对实际题目与回答引用、事实与替代方案、遗漏、虚构、错误归因、内部材料泄漏；部分复盘不含数值或等级，正式进行中无评价。由至少一名领域审核人记录案例和分歧，必要时复核；不把四档直接映射 0～100，不将少量样本声称为准确率或公平性证明。
- **停止条件**：达到负责人批准的费用/调用上限；发现真实敏感信息、评分材料对外泄漏、重复调用不可控、跨场次串数据或无法确认环境隔离时立即停止并保留脱敏证据。若预算、版本或审核人员未确定，不开始调用。
