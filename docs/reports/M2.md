# M2 开发与验收说明

> 以下原始 M2 记录保留历史状态，最新验收结论以文末 M2-08 为准。

## 任务目标

实现服务端模型配置、OpenAI 兼容适配、会话存储和流式聊天，并将专题上下文与普通问答隔离。

## 实际完成

代码已实现服务端环境变量配置、模型流式调用、会话创建/列表/重命名/删除、消息历史、流式输出及中断状态保存、普通聊天页面、专题聊天入口及按专题筛选。首次发送时创建会话。模型密钥不发送给前端。

已通过自动化验证的是模拟模型和 SQLite 下的会话隔离、流式输出与消息保存、缺失配置提示，以及模拟 OpenAI 兼容 SSE 的解析。前端生产构建通过。真实 PostgreSQL、真实模型、浏览器交互和取消操作尚未完成端到端验证，不能视为最终验收通过。

## 关键文件与实现

- `backend/app/core/config.py`、环境变量示例和 `compose.yaml`：服务端读取模型地址、名称、密钥和超时。
- `backend/app/llm/client.py`：使用 HTTPX 流式读取 OpenAI 兼容接口，错误信息不包含上游响应或密钥。
- `backend/app/models/chat.py`、`backend/alembic/versions/0002_chat.py`：增加会话和消息表，专题外键及消息级联删除。
- `backend/app/api/v1/chat.py`：增加会话 CRUD、消息列表及 SSE 接口；断开时尝试保存部分内容与状态。专题正文限制为前 20000 字符，作为上下文发送。
- `frontend/src/pages/ChatPage.tsx`、路由和专题页面：聊天、历史记录与取消入口，复用既有布局和 Markdown 渲染。
- `backend/tests/test_chat.py`：模拟模型和 SQLite API 集成测试。

HTTPX 从原开发依赖调整为运行依赖，显式增加 AnyIO；测试增加 aiosqlite。这些是 V2.5 架构清单之外的具体依赖，并非新服务或架构组件。

## API 与数据库变更

新增 `GET/POST /api/v1/conversations`、`PATCH/DELETE /api/v1/conversations/{id}`、`GET /api/v1/conversations/{id}/messages` 和 `POST /api/v1/conversations/{id}/messages/stream`。会话列表默认仅返回普通会话，传入 `topic_id` 返回该专题会话。新增 `conversations`、`messages` 表；启动时需运行 Alembic 升级至 `0002_chat`。健康接口里程碑由 M1 更新为 M2。

## 测试结果

- `pytest -q`：10 项通过（SQLite、模拟模型）；有测试依赖弃用提示。
- `alembic upgrade head --sql`：离线 SQL 生成通过，不代表真实数据库迁移通过。
- `python -m compileall -q app alembic`：通过。
- `npm run build`：通过。
- Docker 检查：Docker Desktop 已暂停，真实 PostgreSQL 和 Compose 未验证；未配置真实模型，未执行外部模型调用。

## 遗留问题

同一会话的并发限制只适用于单进程；进程意外退出可能留下 `streaming` 消息。长会话未限制历史上下文长度。取消和断线后的持久化尚未在真实 ASGI 服务器、浏览器和 PostgreSQL 组合下验证。当前没有账号隔离、调用限额或公网访问保护。模型返回内容和专题正文不应视为可信指令，现有提示不能保证消除提示注入。

## 下一步建议

启动 Docker 后执行真实 PostgreSQL 迁移、种子和完整 Compose 联调；配置测试模型，验证普通与专题会话、分块输出、取消、异常与刷新恢复；再补充跨进程并发控制、崩溃恢复、上下文预算和浏览器端到端测试，通过后再认定 M2 最终验收完成。

## M2-08 真实联调与验收修复（2026-11-16）

### 目标与修改

在保留学习数据的前提下验证真实数据库、模型和浏览器流程，并修复聊天状态一致性。

- `backend/app/services/chat.py`、`backend/app/api/v1/chat.py`：使用 PostgreSQL 会话级 advisory lock 限制同一会话并发生成；读取或开始新请求时，仅在取得锁后将遗留 `streaming` 消息标记为 `cancelled`。异常清理锁；历史消息按最近优先限制为 24000 字符，专题正文另限 20000 字符。这是字符近似预算，并非精确 token 预算。
- `backend/app/llm/client.py`：区分认证、网络、超时、接口不兼容和其他上游错误，避免返回上游原文或密钥。
- `frontend/src/pages/ChatPage.tsx`、`frontend/src/app/router.tsx`：处理 start/delta/done/error、服务端消息 ID、取消和提前断线；支持 `/assistant/:conversationId` 和专题会话直达、刷新恢复及范围检查。
- `backend/tests/test_chat.py`：增加锁、恢复、上下文预算和模拟错误分类测试。

API 的 SSE `start` 事件新增 `user_id`，原有 `id` 保留。未新增数据库表或迁移，也未引入 V2.5 之外的新依赖。

### 遗留问题与最终验收

**最终验收尚未完全通过。** 浏览器中的硬网络断线、真实 PostgreSQL 上跨进程同时发起完整 HTTP 生成请求、真实多专题切换和进程崩溃后的完整用户流程未做端到端验证；当前验证覆盖连接锁与状态恢复的关键部件，但不能替代这些场景。字符预算不保证适配所有模型的 token 限制；初始创建或开始事件到达前断线时，页面可能需要刷新才能看到服务端已保存的消息。单实例服务仍无账号隔离、公开访问控制和调用限额。

下一步应补齐上述浏览器与多进程故障注入验收，针对目标模型增加 token 预算与历史分页，并按实际部署需要增加访问保护。未开始 M3。
