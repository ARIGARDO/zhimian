# M3-06A 阶段 A 工程报告

## 范围与实现

- `backend/app/models/interview.py`、`backend/alembic/versions/0008_reviewed_question_versions.py`：在题库表增加稳定编号、难度、顺序、审核状态、结构化评价材料、审核人及时间。`(preset_id, content_code, version)` 唯一，部分唯一索引限制每个预设及编号最多一个活动版本；审核与启用分离。PostgreSQL 触发器禁止修改或删除已审核版本，允许切换 `active`。既有无编号记录维持原值，未删除数据；版本仍为整数。
- `backend/app/services/question_version.py`：校验内部参考资料结构，并使用排序键和 UTF-8 JSON 计算覆盖题干、版本、顺序和全部评价材料的 SHA-256。
- `backend/app/services/interview.py`：新 HTTP 创建的版本化题库只接受审核通过且启用的 `bank` 题目；按基础、进阶、挑战及配置顺序冻结题目 ID、编号、版本、题干和摘要。创建时锁定活动题目；新版策略同时记录在预设和配置快照。旧无编号题库不再用于创建新面试；已有旧场次仍可读取及采用旧评价逻辑。`role` 新建场次暂不支持审核题库，需后续专项设计；已有状态机没有重写。
- `backend/app/services/interview_ai.py`：练习反馈、完整和部分报告根据主问题来源引用读取并校验冻结版本及摘要，缺失或篡改时报错；追问不接收评分材料。旧快照未标记新版时使用原题目和完整回答，不追加新版材料。没有重新生成已有报告。上下文预算对完整题目、完整回答及审核材料序列化后的字符数检查，超限直接返回冲突，不创建模型操作或丢弃回答。该预算不是精确 Token 或费用上限。
- `backend/app/llm/client.py`：上游 `finish_reason=length` 显示输出预算错误，避免把截断内容当作完整输出；完整报告仍要求覆盖所有回答 ID，未改变现有候选数字评分字段。没有实现分批评价。
- 测试文件：`tests/test_interview_reviewed.py`、`tests/integration_m306.py`、`tests/test_chat.py`、`tests/test_interview_api.py`、`tests/integration_m303.py`、`tests/integration_m304.py`。测试题库均为独立临时数据，不是正式题库。

## 迁移与回滚

`0008_reviewed_question_versions` 接续 `0007_interview_model_grace`，只增加列、检查、唯一约束、索引和保护触发器，未修改旧迁移。触发器保护已审核题目版本，旧无编号行保留。为避免丢失已发布版本和历史引用，自动 downgrade 被明确阻止；如需回滚代码，应保留新增结构并先评估旧代码与新版本题目的兼容，必要时以前向修复或从经验证的备份恢复。**未连接或修改正式数据库，未执行正式导入或启用。**

## 已知限制与下一步

- 本阶段没有题库导入工具、正式预设及题库数据；审核和启用仍需后续单独授权。旧无编号题库及 `role` 预设不能新建场次，已有旧场次保留旧评价路径；此兼容边界需独立评审。
- 版本不可变依靠 PostgreSQL 触发器；SQLite 仅用于逻辑测试，不能证明锁和触发器行为。审核资料结构在应用层校验，数据库 JSON 本身不验证每个锚点内容。
- 输入预算仅做字符上限，输出上限由模型适配器与上游共同约束；上游未提供截断标记时仍依赖完整 JSON 和回答 ID 校验。3/5/10 题及追问在自动测试中验证了覆盖与超限拒绝，但未对实际供应商的长报告成功率、Token 计费和评价质量做人工验证。
- 正式模式追问不传内部材料，公开接口不返回材料；模型输出过滤仍无法语义证明零泄漏或评价准确性。评分量表、正式题库内容和角色预设复用留待批准。
