# M3-03 面试会话 HTTP API 实施报告

## 范围与架构

基于 M3-02 的 `InterviewService` 实现预设查询、创建、开始、历史/详情、作答、主问题推进和主动终止。状态变更仍在服务层，使用 PostgreSQL 行锁、数据库时间和 M3-02 规则；不开放任意题目正文、动态追问、AI 评分、报告生成或完整页面。没有引入新依赖或修改六项已确认规则。

正式数据库检查结果：`interview_presets` 和 `interview_question_bank` 均为 0 行，**尚无经过审核的正式题库**。本次 API 测试仅在隔离数据库注入带 `test-only` 标识的临时预设与题目，结束后删除测试数据库，未向生产数据库填入或宣传测试题。无可用预设时列表为空；题库未就绪时创建请求返回错误。

主要文件：`backend/app/api/v1/interviews.py`（路由与脱敏错误）、`backend/app/services/interview.py`（预设快照、幂等创建、出题与详情/历史）、`backend/app/models/interview.py` 和 `backend/alembic/versions/0005_interview_create_key.py`（创建幂等字段）、`backend/tests/test_interview_api.py` 和 `backend/tests/integration_m303.py`（API 测试）。`backend/app/main.py` 注册路由、面试异常处理并允许 CORS `Idempotency-Key`。M3-02 报告旧规则表述已清理。

## API 契约

统一前缀 `/api/v1`。所有 POST 必须携带 `Idempotency-Key`，1～100 个 ASCII 字母、数字或 `._:-`；无效或缺失返回 422。请求体不接受未声明字段。日期使用 ISO 8601。

| 接口 | 请求 | 主要响应 |
| --- | --- | --- |
| `GET /interview-presets` | 无 | 已启用预设数组：`id, kind, name, version` |
| `GET /interview-presets/{preset_id}/questions` | 无 | 该预设已启用题目元数据数组：`id, topic, version`；不预先返回题目正文或参考答案 |
| `POST /interviews` | `{preset_id, mode: "practice"\|"formal", limit_type: "count"\|"time", main_limit?, duration_seconds?, jd?}` | 201 `{id, status: "pending"}`；重复同键同体返回相同 ID 和原始创建响应 |
| `POST /interviews/{id}/start` | 无正文 | `{status, started_at}`；不自动出首题或重置计时 |
| `POST /interviews/{id}/questions/next` | 无正文 | `{id, main_number, depth: 0, content}`，从创建时冻结的题目快照按 ID 排序选取下一主问题 |
| `POST /interviews/{id}/answers` | `{question_id, content?, skip?}` | `{id, valid_main_count}`；跳题用 `skip: true` 且正文为空，仅练习模式可用 |
| `POST /interviews/{id}/questions/close` | `{question_id}`，必须是当前主问题 ID | `{status, outcome}`；当前主问题及其已产生追问均已处理后才关闭；最后一主问题关闭才判断题数模式终态 |
| `POST /interviews/{id}/terminate` | 无正文 | `{status}`；主动终止，不能用此接口请求完成或异常中断 |
| `GET /interviews/{id}` | 无 | 状态、模式、预设公开字段、限制、起止/截止时间、原因、计数、版本及已出题和回答；不返回题库计划、评分、评价或参考答案 |
| `GET /interviews?status=completed\|incomplete\|pending\|in_progress&limit=50&offset=0` | 参数可省略，limit 1～100 | 历史数组：`id, status, mode, preset, created_at, ended_at`；`incomplete` 包含主动终止及异常中断 |

创建时校验预设存在且启用、题目启用、题量满足服务端规则和库存、岗位 JD 不超过 5000 字；不做 JD 语义解析。配置、预设版本和可用题目的正文及版本冻结到场次内部快照；关闭题目和获取下一题是两个独立操作。若题目未作答/跳题不能关闭，未关闭不能获取下一题；如果时长模式耗尽题库，返回 409，当前没有自动生成新题的能力，可等待到期或主动终止。

404 表示场次、预设或跨场题目不存在；409 表示状态冲突、题库不足、正式模式跳题、同键不同请求等；422 表示请求结构/范围或有效回答无效；面试接口意外错误返回脱敏 JSON 500。写入时锁内发现时间或无活动到期，状态已提交并返回 409 `{status, outcome, end_reason}`；正常关闭最后一题导致 `completed`/`terminated` 属成功 200。历史和详情读取惰性检查到期；历史会按固定 ID 顺序锁定并结算当前规则版本的进行中场次后再过滤，轮询不延长活动时间，较多同时进行中的场次可能增加锁等待。旧规则快照不会静默改写，详情返回冲突，历史不自动结算其状态。

## 幂等与一致性

创建操作在 PostgreSQL 使用按键派生的事务级 advisory lock，并将全局唯一创建键及请求摘要存入 `interviews`；并发同键同体只创建一场，不同体返回 409。其余写入沿用面试行锁、`interview_operations` 的场次内唯一键和请求摘要；服务层在锁内验证题目归属、终态、截止及配额。相同键重放原始结果，因此重放早先成功的开始/答案响应不代表场次仍在进行，客户端应以详情为准。单独的 `close` 携带主问题 ID 防止旧页面误关闭新题。模型请求并未接入，不存在长事务内模型调用。

正式模式的详情和历史仅输出白名单字段；本轮不生成评价，也不通过 API/SSE 返回评分、评价或参考答案。该单实例没有用户身份认证，预设与会话 ID 的范围检查不提供多用户访问控制。

## 验证结果

- 仓库后端 `pytest -q`：45 项通过（包含 M1/M2、状态机与 HTTP 测试），有 pytest-asyncio 配置和 Starlette TestClient 弃用提示。包括非法配置、重复创建/开始、同题提交、练习跳题、正式跳题禁止、跨场题目、终态、响应字段和内部错误脱敏。
- 真实 PostgreSQL 隔离数据库、两个独立 Uvicorn 进程：并发同键创建只生成一个 ID、重复开始/答案、同键不同体冲突、题数完成、正式模式跳题和跨场保护、并发终止与答案、数据库时间到期/无活动后 HTTP 409 和状态持久化均通过。隔离测试脚本为 `backend/tests/integration_m303.py`。首次执行因测试脚本在两个事件循环间复用 asyncpg 连接失败；改为 `NullPool` 后完整重跑通过。
- 通过标准 `docker compose up -d --build` 构建（最终版本再次重建）；`init` 执行 Alembic 和种子，后端健康。实际运行的后端关键源码哈希与工作区一致，`alembic current` 和 `heads` 为 `0005_interview_create_key`。迁移前 `/tmp/zhimian-m303-before.dump` 已备份；原有 8 个专题、4 条进度、1 个聊天会话及 2 条消息迁移前后逐表校验值一致。
- Compose 入口回归：M1 健康/专题/文章/进度/概览只读通过；M2 创建临时会话调用真实模型并验证 SSE 与消息持久化通过，临时会话已清理；最终重建后再次完成 M1、M2 与 M3 列表的只读检查。

## 待解决与验收建议

1. 尚无经过审核的生产岗位和题库，生产环境无法创建真实面试，必须先由产品提供并审核内容；测试数据不是正式题库。
2. 按时长场次在题库耗尽后没有自动出题或自动正常结束；是否提前结束、增加题库或其他策略待确认。无活动/到期为惰性结算，无请求时状态不会即时改变。
3. 旧规则快照场次不兼容当前规则时拒绝详情/写入，需明确历史兼容或数据迁移策略。当前数据库中无旧面试场次。
4. 历史列表结算全部进行中场次会随并发量增长而增加锁和延迟；生产规模需要评估。部分复盘、AI 追问、报告、租约执行器及正式前端均非本轮实现。
5. 当前单实例没有身份隔离或公网访问保护；开放给不可信用户前需补访问控制。模型与预设内容由维护者审核，不能仅靠 API 保证内容质量。

建议 M3-03 **接口实现通过技术验收**；由于正式题库为空，不能声称用户已能完成生产面试或 M3 全部验收。未开始 M3-04。
