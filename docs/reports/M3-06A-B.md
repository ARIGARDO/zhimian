# M3-06A 阶段 B 题库清单与隔离验收

## 范围与状态

[完整版本化题目清单](../interview/M3-06A-question-manifest.json)包含 20 道题的题干、方向、难度、知识点、目标、参考要点、四档定性锚点、替代答案和误区。清单整体标识 `v1.0-draft`，数据库整数题目版本为 1；所有题目统一为“待审核”，不虚构审核人或启用授权。每方向基础 4、进阶 5、挑战 1；P04 是热点 Key 击穿，P10/A10 为挑战、A07 为基础。参考要点不是唯一正确答案，四档不映射数值。

P01～P03、A01～A04 保留原草案题干；P04 按后续确认的热点 Key 题干修订；其余题目按本轮对话确定的候选内容整理。已依据现有项目实现检查题目技术表述与工程边界，但这不是外部领域专家重新签署的内容审核。未发布草案经批准可修订并重新计算摘要；已审核发布的版本不可覆盖，修改须产生新版本。

## 导入工具与测试

`backend/app/tools/import_interview_draft.py` 是隔离测试专用工具：仅接受 `127.0.0.1` 或 `::1` 上数据库名为 `zhimian_m306b_` 前缀的 PostgreSQL，且要求预先建立专用隔离标记；不迁移数据库、不设置审核人、不自动审核或启用题目。导入在单个事务及 PostgreSQL 事务级 advisory lock 下执行；重复同内容无变化，同版本不同内容失败，不覆盖已审核版本。隔离测试的审核和启用由测试脚本显式分步模拟，不是正式操作。连接参数包含数据库凭据，应使用仅供测试的凭据并避免记录命令历史或日志。

- `cd backend && PYTHONPYCACHEPREFIX=/tmp/zhimian-pycache /tmp/zhimian-m306-py313/bin/pytest -q`：95 项通过；涉及 SQLite、ASGI 和模型替身；pytest-asyncio 与 Starlette 有现有弃用提示。
- 独立 PostgreSQL 容器（无正式数据卷）运行 `M306B_TEST_DATABASE_URL=<隔离库> .../python tests/integration_m306b.py`：通过。包括无隔离标记拒绝、两次导入各 10 题且无重复、同版本内容冲突拒绝、模拟审核与启用分离、基础→进阶→挑战顺序、场次冻结引用和摘要、公开 API 不返回材料、旧 `bank`/`role` 及既有场次。隔离库使用测试预设与内容；没有连接或修改正式数据库。
- 前端类型检查、生产构建及 9 项现有前端测试结果见本轮执行记录；没有改动前端和迁移。
- 未使用真实模型做本轮评价质量测试。可在单独批准、隔离数据及费用上限下，选择两个方向各少量场次，覆盖正确、部分、错误和合理替代答案，由领域人员盲评引用准确性、遗漏、偏差及评分一致性；记录模型版本和费用，不将模拟结果当作真实质量证明。

## 正式发布前确认

1. 产品及领域审核人逐题确认清单、参考要点、替代答案和定性锚点，明确审核人、审核时间、版本及审批记录；确认两套预设名称和启用范围。
2. 设计并单独审批正式导入、审核和启用流程；本轮工具只允许隔离数据库，不能作为正式导入工具直接使用。导入前备份并在隔离环境验证迁移、容量、版本冲突和回滚；不覆盖已发布版本及历史快照。
3. 检查 API、错误、日志和正式模式追问不泄漏内部材料；人工抽检实际模型质量及提示注入风险。确认长报告超出预算时明确失败、不丢回答。
4. 确认候选综合评分量表和算法仍待产品决定，未完成面试只提供无数值、无等级的文字复盘。移动真机、访问控制、历史版本资料保留与运维恢复仍需按既有报告处理。
